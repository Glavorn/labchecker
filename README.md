# LabChecker

Веб-сервис для сдачи и автоматической проверки студенческих лаб (Python/Bash) в курсе ДЕВАП. Студент заходит по личной ссылке и загружает файл, backend прогоняет flake8/shellcheck. Преподаватель смотрит сдачи, принимает или возвращает с комментарием.

## Стек и почему он

- **FastAPI + SQLAlchemy** — простой REST-бэкенд без лишней церемонии, синхронная работа с БД достаточна для нагрузки учебного курса.
- **PostgreSQL** — надёжное реляционное хранение студентов/лаб/сдач, из коробки есть FK и Enum-типы под статусы.
- **flake8 / shellcheck** — готовые линтеры под Python и Bash, не нужно писать свой статический анализатор.
- **Nginx** — единая точка входа: отдаёт статику фронта и проксирует `/api` на backend.
- **Docker Compose** — поднимает db → backend → nginx одной командой, с healthcheck у БД и порядком старта.

## Запуск

```bash
git clone <repo> && cd labchecker
cp .env.example .env   # задать POSTGRES_PASSWORD и TEACHER_TOKEN
docker compose up --build -d
```

Приложение поднимется на `127.0.0.1:8080` (контейнер nginx).

## Kubernetes

Манифесты в `k8s/`: base и два оверлея, local (k3s у себя) и prod (кластер).

```bash
./scripts/k3s-local.sh                # локально, собирает образы и импортирует в k3s
./scripts/push-images.sh 1.1.2        # образы на docker hub
kubectl apply -k k8s/overlays/prod    # перед этим поменять newTag
```

Перед первым деплоем создать `secret.env` и `teacher.env` в папке оверлея по примерам `*.env.example`.

Прод: https://labchecker.135.106.139.37.sslip.io

## Деплой на 67_sandbox

Внешний nginx на сервере уже настроен с SSL для доменов. В его конфиг для нужного (под)домена добавляется блок:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

Сертификаты и остальная инфраструктура — по аналогии с примером конфига, который уже есть на сервере.

## Как пользоваться

Преподаватель заходит через кнопку «Я преподаватель» с токеном из `TEACHER_TOKEN`, добавляет лабы и студентов. При создании студента показывается его ссылка вида `/?key=...`, её надо отправить студенту. Потом ссылку можно перевыпустить, старая перестанет работать. В базе хранится только sha256 от ключа.

Студент открывает ссылку один раз, ключ сохраняется в localStorage. Дальше он загружает файл в нужную лабу и сразу видит результат линтера, строки с замечаниями подсвечены. Если замечаний нет, сдача уходит в очередь «На проверке».

Без токена или ключа доступен только список лаб. Если `TEACHER_TOKEN` не задан, изменять данные нельзя (503).

Swagger: `/api/docs`, в Authorize можно вставить `X-Teacher-Token` или `X-Student-Key`.

## Что можно доделать

- Миграции сейчас через `create_all` и пару `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` при старте. Если таблиц станет больше, лучше перейти на alembic.
- Преподаватель один, токен общий.
